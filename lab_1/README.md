# ЛР1. Приложение на Jakarta EE

Тему для всех лаб взял ближе к ML-ному: база знаний для RAG.

Что умеет приложение: добавлять, редактировать и удалять документы и чанки, резать документ на
чанки с перекрытием и искать чанки по вопросу.

Стек:
- GlassFish 7.1.1 (Jakarta EE 10), запускаю на JDK 21;
- PostgreSQL 16;
- JPA (в GlassFish реализация EclipseLink) для работы с базой;
- stateless EJB для логики;
- JSF для интерфейса;
- Maven, на выходе архив `rag-app.war`.


## База данных

Две таблицы, `documents` и `chunks`, один-ко-многим. У чанка внешний ключ `document_id` с
`ON DELETE CASCADE`, чтобы при удалении документа чанки уходили вместе с ним.

Скрипты в `db/`:
- `00_init.sql` - создаёт пользователя `rag_user` и базу `rag_lab`, потом запускает остальные два;
- `01_schema.sql` - таблицы;
- `02_data.sql` - три документа и девять чанков для старта. Чанки сгенерировал отдельным
  скриптом тем же алгоритмом, что и в приложении, чтобы число токенов совпадало.

Запуск от postgres:

```
"C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -h localhost -f db\00_init.sql
```

Скрипт пересоздаёт базу, если она уже есть. Пароль у `rag_user` учебный (`rag_pass`), он же
прописан в настройках пула на сервере.

## Как устроено

Три пакета, по одному на слой.

**entity** - данные. `Document` и `Chunk` - классы с полями, геттерами и сеттерами (в Java это
называется JavaBean, много однотипного кода) и аннотациями JPA: `@Entity`, `@Table`,
`@Column`, `@OneToMany` / `@ManyToOne` для связи. Там же правила проверки `@NotBlank`, `@Size`. Их проверяет и JSF при отправке формы, и JPA перед
записью.

В `persistence.xml` описан persistence unit `ragPU`. Строки подключения к базе в коде нет вообще,
только JNDI-имя `jdbc/ragDS`. Что за ним стоит, настраивается на сервере. Сначала показалось
лишним, потом понял идею: один и тот же архив можно задеплоить хоть на тестовую базу, хоть на
боевую, не пересобирая.

**service** - логика. `DocumentService` и `ChunkService` помечены `@Stateless`. Это EJB: сервер
держит пул таких объектов и каждый публичный метод сам оборачивает в транзакцию. Вылетело
исключение - откат. `EntityManager`, через который идёт вся работа с базой, подставляется через
`@PersistenceContext`.

Сама логика простая:
- токены считает сервер при каждом сохранении, руками их не вводят;
- токенизатор упрощённый (`SimpleTokenizer`): одно слово, число или знак препинания - один токен.
  С настоящими BPE-токенизаторами числа, конечно, не совпадут, особенно на
  русском, но для лабы сойдёт;
- нарезка фиксированными окнами с перекрытием, например по 40 токенов с перекрытием 10. Старые
  чанки удаляются и новые создаются в одной транзакции;
- поиск по сути bag-of-words: оценка чанка - сколько разных слов вопроса в нём встретилось,
  выводятся Top-K. Никаких эмбеддингов, по-хорошему тут был бы pgvector.

**web** - интерфейс на JSF. Это компонентный фреймворк: страница `.xhtml` состоит из тегов вроде
`h:inputText`, `h:dataTable`, а через выражения `#{...}` они связаны с Java-объектами. На каждую
страницу свой бин (`@Named`). Списки - `@RequestScoped`, живут один запрос. Формы - `@ViewScoped`,
живут, пока открыта страница, иначе между показом формы и её отправкой забывается, что
редактируем. EJB в бины подставляются через `@EJB`. Общая шапка и меню - в
`WEB-INF/template.xhtml`.

Страницы:
- `documents.xhtml` - список документов;
- `document-edit.xhtml` - создание и правка документа;
- `chunks.xhtml` - чанки документа и нарезка;
- `chunk-edit.xhtml` - правка чанка;
- `search.xhtml` - поиск.

## Развёртывание

По заданию деплоить из IDE нельзя, поэтому всё через `asadmin` - это консольная админка
GlassFish.

1. GlassFish скачан и распакован в `server/glassfish7` (в git его нет, весит около 120 МБ).
   У меня в PATH почему-то висит Java 8, на ней сервер не стартует, поэтому сгенерил скрипты для этого:
   `server/glassfish7/glassfish/config/asenv.bat` дописал
   `set "AS_JAVA=C:\Program Files\Java\jdk-21"`. Драйвер PostgreSQL положил в
   `server/glassfish7/glassfish/domains/domain1/lib/`: соединения открывает сервер, так что и
   драйвер нужен ему, а не приложению.
2. Запуск сервера:
   ```
   server\glassfish7\bin\asadmin start-domain domain1
   ```
   Админка открывается на http://localhost:4848.
3. Один раз создать пул соединений и JDBC-ресурс: `deploy\setup-resources.cmd`. Там три команды:
   `create-jdbc-connection-pool` (пул `ragPool` к базе `rag_lab`), `create-jdbc-resource` (имя
   `jdbc/ragDS` для пула) и `ping-connection-pool` для проверки.
4. Сборка и деплой: `deploy\deploy.cmd`. Внутри `mvn package` и
   `asadmin deploy --force=true --contextroot rag-app`.

После этого приложение доступно на http://localhost:8080/rag-app/

Всё то же самое можно накликать в веб-админке: пул в Resources - JDBC - JDBC Connection Pools,
ресурс там же в JDBC Resources, деплой в Applications - Deploy.

Остановить сервер: `asadmin stop-domain domain1`. Лог в
`server\glassfish7\glassfish\domains\domain1\logs\server.log`. Туда же пишется SQL, который
генерирует EclipseLink, - полезно, когда не понимаешь, что ORM там наделал.
